**GalleryGrid** (src/components/shared/GalleryGrid.tsx -- Server Component, NO 'use client'):
- Props: images array (with asset, alt, caption, hotspot, crop, _key), displayStyle ('masonry' | 'grid'), onImageClick callback, columns config (defaults: mobile 2, tablet 3, desktop 4)
- Masonry mode: Use Tailwind responsive classes `columns-2 gap-3 md:columns-3 md:gap-4 lg:columns-4` with `break-inside-avoid` on each item
- Grid mode: Use `grid grid-cols-2 gap-3 md:grid-cols-3 md:gap-4 lg:grid-cols-4` with `aspect-[3/4]` containers and `fill` + `object-cover` on SanityImage
- Each image wrapped in a `<button>` with `type="button"`, aria-label for accessibility, and onClick calling onImageClick(index)
- Subtle hover effect: `group` on button, `transition-transform duration-500 group-hover:scale-[1.02]` on SanityImage, `overflow-hidden rounded` on button container
- Render captions below images when present (text-xs, muted color)
- Use SanityImage component for all image rendering (import from @/components/shared/SanityImage)
- sizes prop on SanityImage: "(max-width: 640px) 50vw, (max-width: 1024px) 33vw, 25vw"
- Do NOT set priority on any gallery image -- all use default lazy loading
- Note: Since GalleryGrid accepts an onImageClick callback (a function), and Server Components cannot receive function props from other Server Components, GalleryGrid will always be rendered FROM a Client Component (GalleryClient). This is fine -- it's the component file itself that matters. GalleryGrid is defined without 'use client' but renders within the client boundary established by GalleryClient.

**GalleryClient** (src/components/shared/GalleryClient.tsx -- Client Component):
- 'use client' directive
- Props: images array, displayStyle, columns config (same as GalleryGrid)
- State: lightboxIndex (number, -1 means closed)
- Renders GalleryGrid with onImageClick setting lightboxIndex
- Conditionally renders GalleryLightbox when lightboxIndex >= 0
- GalleryLightbox loaded via `next/dynamic` with `ssr: false` -- this is the critical performance optimization (zero lightbox JS in initial bundle)

**GalleryLightbox** (src/components/shared/GalleryLightbox.tsx -- Client Component):
- 'use client' directive
- Import Lightbox from 'yet-another-react-lightbox'
- Import Counter from 'yet-another-react-lightbox/plugins/counter'
- Import Thumbnails from 'yet-another-react-lightbox/plugins/thumbnails'
- Import all 3 CSS files INSIDE this component (not in globals.css): styles.css, counter.css, thumbnails.css
- Props: images array, index (current slide), onClose callback
- Map images to YARL slides using urlFor: `urlFor(image.asset).width(1920).auto('format').quality(85).url()` for src, include width/height from asset metadata, include LQIP blurDataURL from asset metadata
- Configure Lightbox: open=true, plugins=[Counter, Thumbnails], counter separator " / ", thumbnails width 80 height 60 gap 8, animation fade 200 swipe 300, carousel preload 2, controller closeOnBackdropClick true
- Do NOT use the custom NextJsImage render function (per RESEARCH.md note -- simpler and more cost-effective to use standard YARL rendering with Sanity CDN URLs that already include auto=format)
- 44x44px minimum tap targets: YARL's default button sizes already meet this, but verify the close button and nav arrows are at least 44x44
