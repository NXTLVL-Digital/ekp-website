Create `src/lib/schemas/` directory with four schema builder files. All use `schema-dts` `WithContext<T>` types and import NAP data from `siteConfig`.

**1. `localBusiness.ts`** — `buildLocalBusinessSchema(): WithContext<LocalBusiness>`
- `@type`: `ProfessionalService` (subtype of LocalBusiness per CONTEXT.md)
- `@id`: `${siteConfig.url}/#business` (export as `BUSINESS_ID` constant for cross-referencing)
- `name`, `url`, `telephone`, `email` from siteConfig
- `address`: PostalAddress from `siteConfig.address` (included in schema for GBP proximity ranking per SAB guidelines — NOT displayed in UI)
- `areaServed`: Array of 7 City objects — Chatham, Danville, Lynchburg, Smith Mountain Lake, Forest, Altavista, Evington — each with `containedInPlace: { '@type': 'State', name: 'Virginia' }`
- `openingHoursSpecification`: Mon-Fri 09:00-17:00, Saturday 09:00-17:00 (by appointment communicated via description, not schema)
- `priceRange`: `'$$$'` (premium portrait photography in mid-size Virginia market)
- `paymentAccepted`: `'Cash, Credit Card, Venmo'`
- `image`: `${siteConfig.url}/og/default.jpg`
- `sameAs`: array of siteConfig.social values (instagram, facebook, tiktok)
- `description`: Brief business description for schema (e.g., "Editorial-style senior portrait and family photographer serving South-Central Virginia.")
- `knowsAbout`: `['Senior Portrait Photography', 'Family Portrait Photography', 'Editorial Photography']`

**2. `service.ts`** — `buildServiceSchema(service: { name: string; description: string; url: string; image?: string }): WithContext<Service>`
- `@type`: `Service`
- `@id`: `${service.url}/#service`
- `name`, `description`, `url` from params
- `provider`: `{ '@id': BUSINESS_ID }` (cross-reference to LocalBusiness — import BUSINESS_ID from localBusiness.ts)
- `areaServed`: `{ '@type': 'State', name: 'Virginia' }`
- `image`: service.image if provided
- `serviceType`: service.name (used by Google to categorize the service)

**3. `faqPage.ts`** — `buildFaqPageSchema(faqs: FaqItem[]): WithContext<FAQPage>`
- Export `FaqItem` interface: `{ question: string; answer: string }`
- `@type`: `FAQPage`
- `mainEntity`: map faqs to `Question` objects with `acceptedAnswer` of type `Answer`
- NOTE: Do NOT include Speakable markup — research confirms it is beta-only for US-English news publishers and may be discontinued in early 2026. The FAQPage structure itself is sufficient for voice search / AI parsing. (Using FAQPage per user decision, but skipping Speakable per research finding — per research: "NOT recommended for implementation")

**4. `review.ts`** — Two exported functions:
- `buildReviewSchemas(testimonials: TestimonialData[]): WithContext<Review>[]` — returns array of individual Review entities
  - Each: `@type` Review, `author` Person, `reviewBody` quote, `reviewRating` Rating (ratingValue: 5, bestRating: 5), `itemReviewed` `{ '@id': BUSINESS_ID }`
- `buildAggregateRatingSchema(testimonials: TestimonialData[]): WithContext<LocalBusiness>` — returns LocalBusiness with aggregateRating only
  - `@type`: `ProfessionalService`, `@id`: BUSINESS_ID, `aggregateRating` with ratingValue 5, reviewCount from testimonials.length, bestRating 5
- Export `TestimonialData` interface: `{ name: string; quote: string; service?: string }`
- NOTE: Per research, self-serving reviews are ineligible for Google star snippets. Implementing for semantic value (AI assistants, non-Google surfaces). Default all to 5-star per CONTEXT.md (hand-picked happy client testimonials).
