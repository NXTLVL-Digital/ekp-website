        _id?: string
        url?: string
        metadata?: {
          lqip?: string
          dimensions?: { width: number; height: number; aspectRatio: number }

    **File 1: src/sanity/lib/fetch.ts — Centralized fetch with ISR**

    Create the `sanityFetch` wrapper function that ALL Sanity data fetching across the site MUST use:

    ```typescript
    export async function sanityFetch<T>({
      query,
      params = {},
      tags = [],
      revalidate = 3600,
    }: {
      query: string
      params?: QueryParams
      tags?: string[]
      revalidate?: number | false
    }): Promise<T>
    ```

    Implementation:
    1. Import `client` from `./client`
    2. Call `client.fetch<T>(query, params, { ... })` with these CRITICAL options:
       - `cache: 'force-cache'` — MUST be explicit. Next.js 15 defaults to `no-store`, which defeats ISR entirely. This is the single most important line in the entire data-fetching layer.
       - `next.revalidate`: Set to `false` when `tags.length > 0`, otherwise use the `revalidate` parameter. Tag-based and time-based revalidation are MUTUALLY EXCLUSIVE in Next.js. Using both causes unpredictable behavior.
       - `next.tags`: Pass the `tags` array directly
    3. Return the typed result

    **CRITICAL NOTE:** Do NOT omit `cache: 'force-cache'`. In Next.js 15, this is the difference between ISR working and every request hitting the Sanity API fresh. The research explicitly flagged this as Pitfall 1.

    **File 2: src/app/api/revalidate/route.ts — Webhook handler**

    Create a POST route handler for on-demand ISR triggered by Sanity webhook:

    1. Import `revalidateTag` from `next/cache`, `parseBody` from `next-sanity/webhook`, `NextRequest` and `NextResponse` from `next/server`
    2. Define `WebhookPayload` type: `{ tags: string[] }`
    3. Check `SANITY_REVALIDATE_SECRET` exists — return 500 if missing
    4. Call `parseBody<WebhookPayload>(req, process.env.SANITY_REVALIDATE_SECRET, true)` — the third `true` argument tells Sanity to wait for CDN to update before responding, ensuring revalidation reads fresh content
    5. Validate signature — return 401 if invalid
    6. Validate body has non-empty `tags` array — return 400 if bad request
    7. Call `revalidateTag(tag)` for each tag
    8. Return `{ revalidated: true, tags: body.tags }` as JSON

    **Sanity webhook setup notes (for documentation, not automation):**
    The webhook must be configured at manage.sanity.io > API > Webhooks with:
    - URL: `https://[deployment-url]/api/revalidate`
    - Trigger on: Create, Update, Delete
    - Filter: `_type in ["siteSettings", "homepage", "servicePage", "gallery", "testimonial", "cityLandingPage"]`
    - Projection: `{"tags": [_type, _type + ":" + slug.current]}`
    - HTTP Headers: `sanity-revalidate-secret: [SANITY_REVALIDATE_SECRET value]`
    - Secret: The same `SANITY_REVALIDATE_SECRET` value
