    **Step 1: Install dependencies**
    ```bash
    npm install resend @react-email/components zod
    ```

    **Step 2: Create Zod schema** (`src/lib/inquiry-schema.ts`):
    - Define `inquirySchema` using `z.object()` with:
      - `name`: `z.string().min(1, 'Name is required').max(100)`
      - `email`: `z.string().email('Please enter a valid email address')`
      - `phone`: `z.string().max(20).optional().or(z.literal(''))` — optional field
      - `serviceType`: `z.enum(['senior', 'family', 'other'], { errorMap: () => ({ message: 'Please select a service type' }) })`
      - `gradYear`: `z.string().optional().or(z.literal(''))`
      - `highSchool`: `z.string().optional().or(z.literal(''))`
      - `message`: `z.string().min(10, 'Please tell us a bit more about your dream session').max(2000)`
      - `website`: `z.string().max(0).optional()` — honeypot field (must be empty)
    - Add `.refine()` for conditional validation: if `serviceType === 'senior'`, `gradYear` must be non-empty (error: "Graduation year is required for senior sessions", path: ['gradYear']). Same for `highSchool` (error: "High school is required for senior sessions", path: ['highSchool']).
    - Export the schema AND export `type InquiryData = z.infer<typeof inquirySchema>`.

    **Step 3: Create rate limiter** (`src/lib/rate-limit.ts`):
    - Constants: `WINDOW_MS = 15 * 60 * 1000` (15 min), `MAX_REQUESTS = 5`
    - `rateLimitMap = new Map<string, { count: number; resetAt: number }>()`
    - Export `checkRateLimit(identifier: string): boolean` — returns true if allowed, false if rate limited.
    - **Lazy cleanup** at start of each call: if entry exists and `now > entry.resetAt`, delete it and create new. This avoids relying solely on `setInterval` which is unreliable in serverless (see Pitfall 4 from research).
    - Also add a `setInterval` cleanup as defense-in-depth (clear stale entries every WINDOW_MS), but don't rely on it.

    **Step 4: Create React Email templates:**

    `src/emails/InquiryNotification.tsx` — Email to Emily when inquiry received:
    - Import from `@react-email/components`: Html, Head, Body, Container, Text, Heading, Hr, Section as EmailSection (avoid name collision)
    - Props: `name: string, email: string, phone?: string, serviceType: string, gradYear?: string, highSchool?: string, message: string`
    - Subject line will be set in Server Action: "New {serviceType} inquiry from {name}"
    - Body: Branded email with Emily Kathryn Photography header, all inquiry details listed clearly, reply-to set to the submitter's email.
    - Styling: Georgia serif font family, brand colors (#1a1a1a text, #b8860b gold accents), max-width 600px, adequate padding.

    `src/emails/InquiryAutoResponder.tsx` — Auto-reply to client:
    - Props: `name: string, serviceType: string`
    - Per user decision: "Warm tone, thank by name, confirm what they inquired about, set response time expectation of 'within 48 hours'"
    - Body:
      - Greeting: "Thank you, {name}!"
      - Confirm: "We received your {senior portrait / family portrait / photography} inquiry and are so excited to hear from you!"
      - Expectation: "Emily will personally review your message and get back to you within 48 hours."
      - Soft sell: "In the meantime, feel free to browse our portfolio for inspiration."
      - Footer: Emily Kathryn Photography | Gretna, VA
    - Same brand styling as notification email.

    **Step 5: Create Server Action** (`src/app/actions/inquiry.ts`):
    - `'use server'` directive at top
    - Import: `z` from zod (for error types), `Resend`, `headers` from next/headers, `checkRateLimit`, `inquirySchema`, both email templates
    - Create `resend = new Resend(process.env.RESEND_API_KEY)`
    - Export `type InquiryState = { success: boolean; message: string; errors?: Record<string, string[]> }`
    - Export `async function submitInquiry(prevState: InquiryState, formData: FormData): Promise<InquiryState>`:

    Processing order (matches research pattern):
    1. **Honeypot check** — if `formData.get('website')` is non-empty, return `{ success: true, message: 'Thank you!' }` (silently reject — don't reveal detection per Pitfall 3)
    2. **Rate limiting** — get IP from `x-forwarded-for` header, call `checkRateLimit(ip)`. If false, return rate limit error message.
    3. **Parse FormData** — construct validation object manually using `formData.get()` for each field (NOT `Object.fromEntries()` which includes `$ACTION_` keys per Pitfall 2). Handle empty strings for optional fields.
    4. **Zod validation** — `inquirySchema.safeParse(data)`. If fails, return `{ success: false, message: 'Please fix the errors below.', errors: validatedFields.error.flatten().fieldErrors }`.
    5. **Send notification to Emily** — `resend.emails.send()` with `from: 'Emily Kathryn Photography <noreply@emilykathryn.com>'`, `to: [process.env.NOTIFICATION_EMAIL!]`, `replyTo: data.email`, `subject: 'New ${data.serviceType} inquiry from ${data.name}'`, `react: InquiryNotification({...data})`. Use env var fallback: if RESEND_API_KEY is not set, log to console and return success (graceful degradation during development).
    6. **Schedule auto-responder** — wrapped in its own try/catch per Pitfall 7. `resend.emails.send()` with `from: 'Emily Kathryn Photography <hello@emilykathryn.com>'`, `to: [data.email]`, `scheduledAt: 'in 10 min'`, `react: InquiryAutoResponder(...)`. If this fails, log error but DON'T fail the submission (notification to Emily is critical; auto-responder is nice-to-have).
    7. Return `{ success: true, message: 'Your inquiry has been sent! We\'ll be in touch within 48 hours.' }`
    8. Wrap entire try/catch: if notification send fails, return `{ success: false, message: 'Something went wrong. Please try again.' }`
